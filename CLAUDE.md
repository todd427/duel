# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Duel runs two independent Claude API sessions side by side. The frontend is a **single file** (`index.html`) — no build, no npm, no framework. The **hosted deploy** (Cloudflare Pages, auto-deployed from `todd427/duel`) adds one server-side **Pages Function** (`functions/api/chat.js`) that injects secrets so the browser never holds any. There is still no server *you* run.

## Hosted / proxy-only (important)

The browser holds **no secrets** and there is **no API-key field or BYOK/direct path**. `streamClaude` always POSTs `{model, system, messages, max_tokens, web, mcp}` (`web` is a boolean, `mcp` an array of server ids) to **`/api/chat`** — the Cloudflare Pages Function (`functions/api/chat.js`), which injects the Anthropic key, web tools, and the selected MCP servers + their tokens, then streams the SSE straight back.

## Running & testing

- **Hosted:** push to `todd427/duel` → Cloudflare Pages auto-deploys. Secrets live in the Pages project env: `ANTHROPIC_API_KEY` plus one bearer per MCP server you want reachable — `MNEMOS_MCP_STATIC_TOKEN`, `RIALU_MCP_STATIC_TOKEN`, `GIT_MCP_STATIC_TOKEN`, and the same `<ID>_MCP_STATIC_TOKEN` pattern for the rest of the registry (the function also accepts `*_MCP_TOKEN`). A server with no token is skipped server-side and greyed out in the picker, so adding one is purely an env-var change. Tokens are in the Taisce vault. Gated by Cloudflare Access.
- **Adding an MCP server:** most of Todd's servers are OAuth-only; Duel needs a long-lived bearer instead. The server's `oauth_provider.py` needs the static-bearer hatch (`self._static = os.environ.get("<ID>_MCP_STATIC_TOKEN", "")` + a `secrets.compare_digest` check at the top of `load_access_token`) — see `mnemos`, `git-mcp`, `tomhas`, `taithi`. Then: mint the token into Taisce, set it as a Fly secret on that app, redeploy, and add it to the Pages env.

  **No code change is needed to add or remove a server.** The Function reads the registry from the env, so adding one is two Pages variables and removing one is deleting them:

  | Variable | |
  |---|---|
  | `<ID>_MCP_URL` | required to add a server not in `BUILTIN` |
  | `<ID>_MCP_STATIC_TOKEN` | the bearer (or `<ID>_MCP_TOKEN`) |
  | `<ID>_MCP_LABEL` | display name (default: the id) |
  | `<ID>_MCP_NOTE` | one-line blurb for the picker |
  | `<ID>_MCP_ALLOW` | comma-separated tool allow-list |
  | `<ID>_MCP_WRITES` | `1` to badge it as write-capable |

  With no `_MCP_ALLOW`, the Function asks the server what it has (`initialize` → `tools/list`, both JSON and SSE transports) and enables what it finds **minus the `DENY` pattern** — which withholds `reveal_*`/`store_*`/`delete_*`/`*_reset` and friends, so a server added by URL alone can't expose secrets or destroy state before anyone has vetted it. An explicit `_MCP_ALLOW` overrides `DENY`. Discovery is memoised per isolate for 10 minutes. **A server only reachable over stdio (or one of Claude.ai's OAuth connectors, like Google Drive) can't be added** — Anthropic dials the MCP server server-side, so it needs a public URL and a long-lived bearer. For the same reason, register the **origin** host, not a canonical one behind Cloudflare Access: `taisce` uses `taisce.fly.dev`, since `taisce.irish` verifies the Access JWT at the origin and 403s a browserless dial.
- **Local dev:** run `wrangler pages dev` so `/api/chat` exists — opening `index.html` as a file no longer works (no proxy). `node --check` on the extracted `<script>` and on `functions/api/chat.js` catches syntax errors; no test suite, verify in a browser.

## Architecture

The frontend is one file (`index.html`); the backend is `functions/api/chat.js`. The `index.html` script section is the whole client app.

- **Two panes, keyed `left` and `right`** throughout the code (these are α Alpha / β Beta in the UI). Almost every function takes a `side` argument of `'left'` or `'right'`. DOM IDs follow the pattern `model-<side>`, `sys-<side>`, `msgs-<side>`, `pane-<side>`.
- **`histories = { left: [], right: [] }`** — the two panes have completely separate conversation histories (the whole point of the tool: no shared context). Each entry is an Anthropic-format `{ role, content }` message.
- **`streamClaude(side, userText, attachments, hooks)`** — the core API call. Reads model/system-prompt from the DOM, pushes the user message to `histories[side]`, POSTs to `/api/chat` (with the `web` boolean and the `mcp` server-id array), and parses the SSE body via a `getReader()` loop. It **reconstructs the assistant content blocks** by index from `content_block_start/delta/stop` (text via `text_delta`; server-tool input via `input_json_delta`), calls `hooks.onText(accumulated)` per text delta and `hooks.onTool(label)` when a `server_tool_use`/`mcp_tool_use` block completes, captures `stop_reason`, and pushes the **full block array** (text + any tool blocks) to history. It loops to resume on `stop_reason === 'pause_turn'` (guarded). `runStream(side, …)` wraps it: `ensure()` swaps the thinking dots for a live bubble (`startAssistantMsg`, which has a `.tools` chip row) on the first text **or** tool event, then `finalizeAssistant` re-renders and adds the cross-send button (plus a truncation note if `stop_reason === 'max_tokens'`).
- **Web + MCP context are built server-side** in `functions/api/chat.js`. The frontend sends `web` (header `#webToggle`, persisted `duel_web`) and `mcp` — an array of server ids from the header MCP picker (`#mcpBtn`/`#mcpPanel`, persisted `duel_mcp`, defaulting to `mnemos`+`rialu`). The Function turns those into web tools — `web_search_20260209` + `web_fetch_20260209` (dynamic filtering) for models matching `WEB_MODERN`, falling back to `web_search_20250305` + `web_fetch_20250910` for Haiku 4.5 and older — and the MCP connector (`mcp_servers` + an `mcp_toolset` per server, beta header `mcp-client-2025-11-20`). **The per-tool allow-list is enforced there** via `default_config:{enabled:false}` + explicit `configs`; the browser can ask for a *server* but never for a *tool*. Every server is read-only (Taisce is metadata-only — `reveal_*` is never enabled) **except `git`, which is deliberately write-capable** (`git_add`/`git_commit`/`git_push`/`git_write_file`/`git_branch`/`git_checkout`); destructive git ops (`delete_file`, `reset`, `reclone`, `merge`) are still withheld. `GET /api/chat` returns `{servers:[{id, label, note, writes, ready, tools, discovered}]}` — it **is** the picker's list, so the frontend has no server registry of its own. A server with a token but `tools: 0` is shown disabled as *unreachable* rather than dropped silently, because a silent drop reads exactly like the server being down. Web/MCP calls stream back as `server_tool_use`/`mcp_tool_use` + result blocks (handled by the same generic reconstruction); chips are `🔍 searched` / `🌐 fetched` / `🧠 <server>: <tool>`. Assistant history entries are **block arrays**, not strings — `exportMd` filters `type === 'text'`.
- **`send()`** — driven by the **route** (`left` / `right` / `both`). For `both`, fires `runStream` to both panes in parallel via `Promise.all`. Guarded by a global `busy` flag.
- **`crossSend(content, targetSide)`** — takes one pane's response and injects it as a *user* message into the other pane. The ✕/sigil button on each assistant message wires this up (`appendMsg` adds it; target is the opposite side).
- **`buildContent(text, attachments)`** — converts pending attachments into Anthropic content blocks: images → base64 `image` blocks, PDFs → `document` blocks, text/code → fenced code prepended as text. `pendingFiles` holds staged attachments; `attachFiles`/`removeFile`/`renderStrip` manage the attach strip.
- **`renderMd(text)`** — a small hand-rolled Markdown renderer (code fences, inline code, lists, paragraphs). There is no Markdown library.
- **`exportMd()`** — serializes both `histories` into a single timestamped Markdown file for download.
- **Spend tracking** — `recordUsage(model, u)` runs once per response with usage parsed from the stream (`message_start` → input/cache tokens, `message_delta` → output tokens), priced via the `PRICING` map (per-1M; cache read ≈0.1×, write ≈1.25×), accumulated into `spend` (persisted `localStorage` `duel_spend`), shown in `#spendBtn` (click → `resetSpend()`). Update `PRICING` when prices or the model list change (it's separate from the `<select>` options). Cost excludes web-search/tool surcharges — it's token-based.

## Conventions & constraints

- **Keep the frontend single-file and dependency-free.** All HTML/CSS/JS stays in `index.html`; no build step, npm, or CDN imports unless explicitly asked. The only backend is `functions/api/chat.js` (a Cloudflare Pages Function) — keep it dependency-free too (Workers runtime only).
- **Tool/MCP definitions live in `functions/api/chat.js` only** (web-tool versions, MCP server URLs, per-tool allow-lists, the `*_MCP_STATIC_TOKEN`/`*_MCP_TOKEN` env lookups). The frontend just sends the `web` flag and server ids, and builds its picker from `GET /api/chat`; `MCP_SERVERS` in `index.html` is a **runtime cache of that response**, not a list to maintain — never reintroduce a hardcoded server list there. Model lists live in the two `<select id="model-<side>">` elements; everything tool/server-related is in the Function.
- `left`/`right` are the internal identifiers; α/β/Alpha/Beta are display labels only.
- **Accessibility: all four themes must hold WCAG AAA text contrast (≥7:1).** Each theme defines `--text` / `--text-dim` / `--text-faint` (all ≥7:1; dim ~8:1) plus `--left-ink` / `--right-ink` (text-legible accent variants — accents themselves are kept vivid for borders/dots/tints and are **not** contrast-safe as text), and `--error` / `--warn`. Use `--*-ink`/`--error`/`--warn` for any *text*; reserve `--*-accent` for borders/backgrounds. Don't apply `opacity` to already-dimmed text. If you touch theme colors, re-verify with the contrast math (composite alpha over `bg`/`surface`/`surface2`, worst case is `surface2`).
- **Responsive type:** readable content (message body/code/headings + compose) sizes off `--msg` = `clamp(13.5px, 0.5vw + 8px, 20px) × var(--fs)` — auto-scales with viewport width. The `A−/A+` control (`bumpFont`) sets `--fs` (0.8–1.6, persisted `duel_fs`). Chrome (header, labels, toggles) stays fixed-size on purpose. The app shell is `100dvh` flex-column (header / `.panes` flex:1 / input-area) — it already fills the viewport.
- **Persistence (all `localStorage`):** theme (`duel_theme`); web toggle (`duel_web`); MCP server selection (`duel_mcp`); text scale (`duel_fs`); spend (`duel_spend`); system prompts + model choices + max-tokens (`duel_settings`, via `saveSettings()` over `PERSIST_IDS`). No secrets are stored client-side. Four themes live as CSS via `data-t` attributes and `setTheme()`.
- **Presets** (`PRESETS` + `applyPreset`) fill both `sys-<side>` textareas from the header `#presetSel` dropdown; add new pairs to the `PRESETS` map and a matching `<option>`.
- Supported models are hardcoded in the two `<select id="model-<side>">` elements — update both panes when changing the list.
- `max_tokens` comes from the `#maxTokens` input via `maxTokens()` (default 32000, client-clamped 256–128000), then the Function re-clamps per model — 128K for `OUT_128K` (Fable/Mythos 5, Opus 5/4.8/4.7/4.6, Sonnet 5/4.6), 64K for Haiku 4.5 — so the two panes can run different ceilings. Don't lower the default: thinking tokens come out of this budget on the models that reason by default, and the old 4096 truncated answers to a preamble (a one-time `duel_tokens_v2` migration lifts anyone still on it); `anthropic-version` is `2023-06-01`. Requests use `stream: true` — keep new API code on the SSE path.
